# 📚 Course Vault · 课程资料共享库

> 一门课的资料，不该让每一届都从零攒起。

这里是面向本校同学的开放课程资料库：**笔记、作业、实验报告、课件、历年试卷、复习攻略**，由历届同学自愿上传，非营利，只要仓库还在就一直免费。

> ⚠️ **当前状态：试运行 / 认领中**。课程目录已经建好，但**绝大多数课程还没有资料**，卡片里写着「待补充」的字段需要上过这门课的人来填。别指望现在能在里面搜到期末原卷。

**第一次来，先看这三份：**
- [INDEX.md](INDEX.md) —— 有哪些课、难度几星、资料全没全
- [CONTRIBUTING.md](CONTRIBUTING.md) —— 上传规则、命名规范、什么不能传
- [docs/新手上传教程.md](docs/新手上传教程.md) —— 手把手教你第一次上传
- [docs/治理与审核方案.md](docs/治理与审核方案.md) —— 有人乱传、被破坏、被投诉时怎么处理

授权与免责见 [LICENSE](LICENSE)，侵权投诉见 [TAKEDOWN.md](TAKEDOWN.md)。

## ✨ 这个仓库解决什么问题

| 痛点 | 这里的答案 |
|---|---|
| 期末不知考什么 | 历年试卷 + 复习攻略 + 考点清单 |
| 老师 PPT 课后就删 | 课件按课程归档，随时回看 |
| 实验报告格式不会写 | 参考往届同款报告的结构与评分点 |
| 资料只在群里刷屏 | 一次上传，长期可查，不丢不沉 |
| 选课前不知道水深 | 课程 README 里写清考核方式、难度、避坑点 |

## 📂 目录结构

```
courses/
├── 公共课/
│   └── 高等数学/                  # 全校通用课：一门课一个文件夹
│       ├── README.md              # 课程卡片（必填）
│       ├── 笔记/                  # 笔记、错题、知识点整理
│       ├── 课件/                  # 课件 PPT / PDF
│       ├── 试卷/                  # 历年试卷、模拟卷、答案
│       └── 作业/                  # 作业、实验报告（参考件）
└── 专业课/
    └── <学院名>/                  # 例如：医学院、计算机与信息技术学院
        └── <专业名>/              # 例如：康复治疗学、计算机科学与技术
            └── <课程名>/          # 例如：人体解剖学、数据结构
                ├── README.md
                ├── 笔记/
                ├── 课件/
                ├── 试卷/
                └── 作业/
```

> 注意层级不一样：**公共课是两层，专业课是四层**（专业课依次是「学院 → 专业 → 课程」，因为不同学院/专业有同名课程，比如「人体解剖学」好几个专业都要上）。

新建课程，两种办法：

```bash
# 一键版：跑脚本，按提示填空，目录和卡片自动生成
python3 scripts/new_course.py

# 手动版：复制 _template/ 整个文件夹 → 改名成课程名 → 填好 README
```

## 🚀 上传前必须知道的一件事

**你没有这个仓库的写权限，就不能直接点 `Add file`**——按钮点下去会提示没权限，或者要求 Fork。这是最多人卡住的地方。所以先分清两种情况：

- **你是仓库成员（被邀请的协作者）** → 走方式一，直接传
- **你不是成员（绝大多数同学）** → 推荐走方式三：填「上传资料」表单，机器人自动归档并开 PR，不用 Fork；想自己控制文件位置再走方式二 Fork + Pull Request

---

## 方式零：连 GitHub 都不碰（最省事，大多数人走这条）
1. 把文件（笔记照片、PPT、试卷照片都行）直接发给资料库维护者：在班级/学院群里问一句，或在仓库开个 Issue 留言
2. 说清楚三件事：**哪门课 + 哪个学院哪个专业 + 这是什么资料（年份/学期/类型）**
3. 维护者替你放进对应文件夹、改好规范文件名、提交入库，你一步都不用点

> 传之前自己扫一眼：**含姓名、学号、手机号、身份证的页就删掉或涂掉再发**。

## 方式一：直接上传（仅仓库成员）

1. 进到目标课程文件夹（公共课两层，专业课四层）
2. 点 `Add file` → `Upload files`
3. 选文件，底部填一句说明，点绿色 `Commit changes`

## 方式二：Fork + Pull Request（普通同学的正路）

```
① 仓库右上角点 Fork              → 你账号下多出一份自己的副本
② 在自己那份里进目标文件夹        → Add file → Upload files → Commit changes
③ 回到官方仓库点 Pull requests    → New pull request → 选你的分支 → Create
④ 维护者审核合并                 → 资料就进官方库了
```

不用命令行，全程网页就能做完。第一次大概 5~10 分钟，比装 Git 快。

## 方式三：填一张表就行（不用 Fork、不用懂路径、不用改 INDEX）

只要有 GitHub 账号，会点网页表单就够了：

```
① 仓库顶部点 Issues → New issue → 选「上传资料」
② 按表单填写/选择：课程类别 → 开课学院 → 所属专业 → 课程名称 → 年份学期 → 资料类型
③ 把文件直接拖进「附件」框（最多 5 个，每个不超过 50MB）
④ 点 Submit new issue
⑤ 维护者确认后点一个 approved 标签
⑥ 机器人自动下载、按规范命名、归档到 courses/，并开一个 PR
⑦ PR 的「结构与内容检查」CI 通过后，由维护者合并
```

整个过程**不需要 Fork、不需要知道文件该放哪个路径、也不需要手动改 `INDEX.md`**。机器人会按表单里的学院 / 专业 / 课程自动归档；课程名必须与仓库里已有的课程文件夹名完全一致（下拉框和输入框里都有提示）。

> ⚠️ Issue 是公开的：不要把含姓名、学号、联系方式的 PDF 直接拖进去——删了还有缓存和引用。表单最后一项必须勾选确认。

## 方式四：Git 命令（批量传，老手用）

```bash
git clone https://github.com/7620qwertqwert-beep/course-vault.git
cd course-vault
# 把文件放进对应课程目录
git add .
git commit -m "add: 高等数学 2025秋 期末试卷"
git push        # 没权限就推到自己的 fork，再开 PR
```

> 超过 50MB 的文件会被 CI 体积检查拦下（`.gitignore` 只忽略压缩包/视频等扩展名，不按大小拦截）；请走网盘 + 在课程卡片里登记链接。

## 📝 命名规范（重要，不然会乱成一锅粥）

```
<年份><学期>-<类型>-<描述>.<后缀>

例：
2025秋-期末-高等数学A卷.pdf
2025秋-期末-高等数学A卷-参考答案.pdf
2026春-笔记-第一章极限.md
2025秋-实验报告-测量数据处理.docx
```

- 学期：`春` / `秋`
- 类型固定用：`期末` `期中` `笔记` `作业` `实验`（或 `实验报告`）`课件` `复习` `答案`
- 文件名不带姓名、学号、老师私人联系方式

## 🚫 不要上传这些

- 带**个人姓名、学号、身份证号、联系方式**的任何文件（提交前一定检查页眉页脚和文档属性）
- 老师明确声明**不得外传**的材料（内部讲义、未公开试卷）
- 受版权保护的**正版教材 PDF**（教材只登记书名 + ISBN + 版本，不传全文）
- 单个超过 **50 MB** 的文件（走 Issue 给网盘链接）

## 🤖 自动检查（每次改动都会跑）

任何 PR 提交后，GitHub 会自动跑一遍检查，**没过就不能合并进 main**：

| 检查项 | 不过的后果 |
|---|---|
| 目录结构与命名规范（PR 时使用 base 分支的 `scripts/check.sh`） | 挡住合并 |
| 索引与目录不一致（PR 时使用 base 分支的 `scripts/build_index.py --check`） | 挡住合并 |
| 单个文件 > 50MB | 挡住合并 |
| 单 PR 新增/修改文件总体积 > 100 MiB | 挡住合并 |
| 空文件超过 5 个（疑似灌水） | 挡住合并 |
| 一次删除超过 20 个文件（疑似批量破坏） | 挡住合并 |
| 改到 `LICENSE` / `scripts/` / `.github/` / 文档等治理文件 | 挡住合并（需维护者亲自处理） |
| 非常规路径（`courses/**`、`INDEX.md` 以外） | 挡住合并 |
| 重复内容文件 | 仅警告，人工判断 |

另外 `main` 分支本身也有保护：**不能直接推、不能强推、不能删分支**，一切都得走 PR。
